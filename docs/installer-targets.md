# Installer target interface
`nci-si-install plan` describes a target and optional index, documentation and companion. The MCP server is always selected. **check prerequisites → install → configure → verify**
The local target runs those stages through the same resumable state path. `run --transport stdio --profile unified` names the defaults; transport also accepts `http`, and profile accepts `evs` or `cadsr`. Install creates owned `venv`, `server-data` and `runtime` children and installs only the exact release tag represented by the running installer. A development-version installer is BLOCKED. Verification reads the installed version and PEP 610 requested revision rather than trusting the install command.
Local server checks cover macOS/Linux, the running Python 3.14 or newer, the Git executable used by pip for the released VCS URL, and the configured EVS/caDSR endpoints. They require neither PDM nor a Git checkout. Selected documentation or companion components add their own Node/container tools and ports 8080/8081. Checks change nothing. Expected failures carry static corrections; bugs propagate. AWS executable checks arrive with #324. `local` is executable. Standard-account `aws` is plannable; `cloud-one` only reports its block on [#292](https://github.com/CBIIT/nci-si-mcp/issues/292). AWS companion administration awaits [#197](https://github.com/CBIIT/nci-si-mcp/issues/197). Azure and GCP have no implementation; future targets use the same flow without plugins.
`run` and `status` require `--data-dir`; `NCI_SI_DATA_DIR` belongs to the server. Reconciliation and the status snapshot hold `installer-state.lock`. State version 2 binds the target, components, local transport and domain profile. Version 1 is refused without migration. State uses an fsynced temporary sibling, atomic replacement and a directory fsync.
Non-restart runs reverify from the beginning; the first stale step and later records are discarded. Missing prerequisites are BLOCKED with static corrections; verifier failures with no missing input are FAILED. `--restart` clears recorded progress for the same selection but deletes no installed assets. Another selection requires a new `--data-dir`. Invalid, truncated or unsupported state remains unchanged. On a terminal, BLOCKED `run` prints fixes to stderr; Enter rechecks and EOF returns BLOCKED JSON. Non-TTY stdin and `--non-interactive` never read input. `help <step> --target local` explains every executable stage.

stdio configuration prints an owned executable suitable for a client and opens no listener. HTTP binds `127.0.0.1`, uses trusted-local access and explicitly sets `NCI_SI_HTTP_REQUIRE_INDEX=0` until index assets are selected in #321. HTTP verification reuses only a token-matched owned process; otherwise it starts a transient process, checks `/ready` and stops it. An unowned listener on port 8000 is BLOCKED. `start` and `stop` operate the recorded HTTP process. `uninstall` refuses a running owned process, removes only the three owned children, then removes installer state so later status reports no installation.
